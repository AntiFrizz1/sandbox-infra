# Миграция sandbox-infra

Для security-remediation использовать [SECURITY-RUNBOOK.md](SECURITY-RUNBOOK.md)
и [текущий статус](SECURITY-REMEDIATION-STATUS.md). Установка нового hook меняет
совместимость Node/Docker; требуется инвентаризация до обновления.

`migrate.sh audit` только читает состояние. `state --dry-run` и `sites --dry-run`
показывают операции. Изменяющие `state`, `sites` и `sites --revert` используют
тот же project lock, что deploy. Неблокирующий status lock не берёт.

`sites` сохраняет полный tar в закрытом `/var/backups/sandbox/<project>/...`
(путь можно явно переопределить `SANDBOX_MIGRATION_BACKUPS`), проверяет backup,
публикует очищенную копию и карантинирует unsafe-оригинал вне раздачи.
Уже мигрированные releases также проверяются. Если очистить активный release
нельзя, проект снимается с раздачи и операция сообщает об ошибке. Остальные
завершённые операции не откатываются автоматически.

`sites --revert` возвращает в плоскую раскладку только безопасный current;
unsafe backup не восстанавливается публично. Проверка пути выполняется до
первого перемещения. Остальные releases при revert удаляются: сначала
сохранить закрытый snapshot нужной истории. `site.flat`/`site.migrating` и
выходящие или промежуточные ссылки вызывают отказ без исправления наугад.

`repair-permissions.sh --dry-run`/без флага исправляет private state/logs/env,
не трогает application data и volumes. Исторические PoC аудита хранятся
отдельно и в репозиторий не входят; их сценарии перенесены в отрицательные
регрессионные тесты (`tests/test_security.sh`).

Подробный пофазный план перехода со старой раскладки (инвентаризация,
переименование проектов, ручные эквиваленты команд, верификация) сохранён в
[MIGRATION-LEGACY.md](MIGRATION-LEGACY.md) с пометками о том, что изменилось.
