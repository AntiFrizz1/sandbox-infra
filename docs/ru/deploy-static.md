# Деплой статического сайта

HTML, CSS, JS и картинки без сборки. Никаких политик на сервере не нужно:
хук копирует каталог сайта в новый релиз, а Caddy раздаёт его по
`https://<app>.sandbox.<домен>`.

## Структура репозитория

```
my-site/
├── public/            ← публикуется только это
│   ├── index.html
│   ├── style.css
│   └── img/logo.png
├── .sandbox.conf      ← необязательно
└── README.md          ← не публикуется
```

`.sandbox.conf` (пример — `examples/static.sandbox.conf`):

```
type=static
publish_dir=public
spa=false
```

Если `.sandbox.conf` нет, а в корне нет `package.json`, compose-файла и
`Dockerfile`, проект считается статическим с `publish_dir=public`.

## Имя проекта

1–63 символа: строчные латинские буквы, цифры и дефис, дефис не первым и не
последним. Имя становится поддоменом: `my-site` → `https://my-site.sandbox.<домен>`.

## Первый деплой

Через клиент (см. [установку](install.md#5-настроить-клиент-на-своей-машине)):

```bash
cd my-site
git init && git add -A && git commit -m "first"
sandbox-deploy init my-site     # создаёт репозиторий на VPS и remote prod
sandbox-deploy push             # пушит и ждёт исхода деплоя
```

Без клиента:

```bash
ssh deploy@<VPS> /srv/deploy/new-app.sh my-site
git remote add prod ssh://deploy@<VPS>/srv/git/my-site.git
git push prod main
```

Деплоит только ветка `main`. Клиент отправляет `HEAD` в `main`, поэтому
локальная ветка может называться как угодно; при обычном `git push` пушь
именно в `main`. Если сборка провалилась, `git push` всё равно покажет
успех — хук не может отменить принятый пуш. Об этом скажет строка
«✗ ДЕПЛОЙ ПРОВАЛЕН» в выводе, а `sandbox-deploy push` завершится с ошибкой.

## Что происходит при push

1. Хук берёт ровно запушенный коммит (`git archive`) в чистый каталог —
   остатки прошлых сборок не попадают в новую.
2. Копирует `publish_dir` в `/srv/sites/<app>/releases/<sha>/` без:
   - dot-файлов и каталогов (кроме `.well-known`),
   - `.env`, `.env.*`, `*.env`, `.sandbox.conf`,
   - ключей: `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`,
   - корневого `node_modules`.
   Симлинк, ведущий за пределы `publish_dir`, останавливает деплой.
3. Атомарно переключает `current` на новый релиз. Если что-то упало раньше,
   сайт продолжает отдавать предыдущую версию.

Caddy дополнительно отвечает 403 на dot-пути, `.env` и ключи — даже если
такой файл каким-то образом окажется в релизе.

## SPA без сборки

Если сайт — одностраничное приложение с маршрутизацией в браузере
(прямой заход на `/about` должен отдать `index.html`), включи `spa=true`.
Fallback срабатывает только для путей, похожих на маршрут: существующие файлы
отдаются как есть, а отсутствующие `.js`, `.css`, шрифты и картинки честно
возвращают 404.

## Сайт в корне репозитория

Если файлы лежат в корне, нужен явный `publish_dir=.`
(`examples/legacy-root.sandbox.conf`). Секреты и dot-файлы и тогда не
публикуются, но исходники и всё остальное — да. Лучше перенести сайт в
`public/`.

## Управление

```bash
sandbox-deploy status [my-site]          # активный релиз и последний деплой
sandbox-deploy logs [my-site] [sha|--list]
sandbox-deploy rollback [my-site]        # на предыдущий релиз, без пересборки
sandbox-deploy rollback [my-site] --list # сохранённые релизы
sandbox-deploy redeploy [my-site]        # пересобрать main без нового коммита
sandbox-deploy stop [my-site]            # снять с раздачи, релизы сохраняются
sandbox-deploy remove [my-site]          # удалить всё безвозвратно
```

Имя можно не указывать — оно берётся из remote `prod`. `-y` отключает
вопросы. Хранятся пять последних успешных релизов; текущий не удаляется
никогда. После `stop` проект возвращается командой `rollback`.

На сервере то же самое — скрипты `/srv/deploy/*-app.sh` от пользователя
`deploy`.

## Если что-то не так

| Симптом | Причина |
|---|---|
| «каталог публикации 'public' непригоден» | в коммите нет `public/` — проверь `git ls-files public` |
| пустой 404 на любой путь | проект ещё ни разу не деплоился успешно или остановлен (`status`) |
| 404 «Unknown sandbox project» | имя в адресе не подходит под правило имён проектов |
| вложенный путь даёт 404 | для SPA нужен `spa=true` |
| файл есть в репозитории, но не отдаётся | он попадает под исключения (dot-файл, `.env`, ключ) |
